# ما هو Node.js، وكيف يختلف عن المتصفح

**Node.js** هو بيئة تشغيل JavaScript (Runtime Environment) تعمل على الخادم أو جهاز الكمبيوتر المحلي، بينما **المتصفح** هو بيئة تشغيل JavaScript التي تتفاعل مع واجهة المستخدم الرسومية (GUI).

كلاهما يستخدم لغة JavaScript، لكن مواضع التشغيل والواجهات البرمجية المتاحة والاستخدامات مختلفة تمامًا.

---

## 🖥️ ما هو Node.js

Node.js هو بيئة تشغيل JavaScript مبنية على محرك **V8** من Chrome. يزيل واجهات برمجة التطبيقات الخاصة بالمتصفح (مثل DOM)، ويضيف بدلاً من ذلك واجهات برمجة التطبيقات على مستوى نظام التشغيل، مثل عمليات الملفات وعمليات الشبكة وغيرها.

هذا يتيح لك استخدام JavaScript لكتابة:

- أدوات سطر الأوامر
- خدمات الويب الخلفية
- التطبيقات المكتبية
- وغيرها

يعتمد Node.js على نموذج الإدخال/الإخراج **غير المتزامن والمدفوع بالأحداث**، وهو مناسب للسيناريوهات ذات التزامن العالي.

---

## 🌐 الاختلافات الجوهرية عن المتصفح

الفرق الأساسي بين الاثنين يكمن في **البيئة** و**الواجهات البرمجية المتاحة**:

| بُعد المقارنة                  | المتصفح                                               | Node.js                                                                 |
| ------------------------------ | ----------------------------------------------------- | ----------------------------------------------------------------------- |
| **الاستخدام الأساسي**          | التفاعل مع المستخدم، تشغيل واجهة الويب                | تشغيل الخادم، أدوات سطر الأوامر، المعالجة الخلفية                       |
| **الواجهات البرمجية الأساسية** | DOM، BOM، Cookie وغيرها من واجهات منصة الويب          | نظام الملفات (`fs`)، الشبكة (`http`/`net`)، العمليات (`process`) وغيرها |
| **التحكم في البيئة**           | لا يمكن التحكم في المتصفح وإصداره الذي يستخدمه الزائر | يمكن التحكم بدقة في إصدار Node.js والبيئة                               |
| **نظام الوحدات**               | يدعم بشكل أساسي ES Modules (`import`)                 | يدعم في نفس الوقت CommonJS (`require`) و ES Modules                     |

> **ملاحظة:** على الرغم من أن Node.js يزيل DOM، إلا أنه لا يزال بإمكانك استخدام JavaScript في Node.js لمعالجة البيانات، وبناء الخوادم، وكتابة السكريبتات. تهدف كلتا البيئتين إلى تمكين JavaScript من العمل، لكنهما توفران "قدرات" مختلفة.

# What npm is for :

## يعني إيه npm؟

`npm هو مدير الحزم (Package Manager) الخاص بمنصة Node.js في JavaScript. وظيفته الأساسية إنه يساعدك تثبّت، تدير، وتشارك الحزم (packages) بسهولة، وبكده بيحل مشكلة إعادة استخدام الكود وإدارة الاعتماديات (dependencies).`

- 📦 بيتكوّن من 3 أجزاء أساسية
- npm مش مجرد أداة سطر أوامر، هو بيتكوّن من تلات حاجات:

- الجزء وظيفته
  `CLI (سطر الأوامر)	الأداة اللي بتستخدمها في التيرمنال، وأشهر أمر فيها هو npm install لتثبيت الاعتماديات Registry (السجل)	قاعدة بيانات عامة ضخمة فيها آلاف الحزم مفتوحة المصدر، وبتنزّل منها الكود افتراضياً الموقع (Website)	بتستخدمه للبحث عن الحزم، وإدارة حسابك، ومشاهدة التوثيق`

## 🎯 الاستخدامات الأساسية

1. تثبيت الاعتماديات (أشهر استخدام)

- لما تنزّل مشروع حد تاني أو تحتاج تستخدم مكتبة خارجية، بتشغّل:

- bash
- npm install
- فبيحمّل كل الحزم المطلوبة تلقائياً ويحطها في فولدر node_modules.

2. النشر والمشاركة

- تقدر تنشر الكود اللي كتبته كـ package على الـ Registry عشان الناس حول العالم تستخدمه.

3. إدارة الإصدارات

- بيتعامل بذكاء مع الاعتماديات بين الحزم المختلفة عشان يتجنب التعارضات، وبيسمحلك تحدد إصدار الحزمة اللي بتستخدمها في مشروعك.

## 💡 معلومة صغيرة

`رغم إن ناس كتير فاكرة إن npm اختصار لـ "Node Package Manager"، إلا إنه رسمياً مش اختصار، لكنه اختصار تكراري لـ "npm is not an acronym" (يعني npm مش اختصار). بس ده مش بيأثر  لى فهمك ليه كمدير حزم.`

## 🔧 أوامر شائعة هتحتاجها

- bash
- npm init # إنشاء ملف package.json لمشروعك
- npm install # تثبيت كل الاعتماديات
- npm install express # تثبيت حزمة معينة
- npm install -D nodemon # تثبيت حزمة كـ dev dependency
- npm uninstall express # إزالة حزمة
- npm update # تحديث الحزم
- npm run start # تشغيل سكريبت معرّف في package.json

## خلاصة:

## ` npm هو "المتجر + أداة التثبيت + مدير الاعتماديات" بتاع عالم Node.js — من غيره هتضطر تنزّل كل مكتبة يدوياً وتدير تعارضاتها بنفسك، وده شبه مستحيل في المشاريع الكبيرة.`

# الفرق بين Git و GitHub

## الفرق باختصار

|                   | Git                                         | GitHub                                 |
| ----------------- | ------------------------------------------- | -------------------------------------- |
| **إيه هو؟**       | نظام إدارة إصدارات (Version Control System) | منصة استضافة سحابية للكود              |
| **النوع**         | برنامج/أداة بتثبتها على جهازك               | خدمة على الإنترنت                      |
| **بيشتغل فين؟**   | على جهازك (محلياً)                          | على السيرفرات (عن بُعد)                |
| **مين عمله؟**     | Linus Torvalds (2005)                       | شركة GitHub (2008)، مملوكة لمايكروسوفت |
| **الوظيفة**       | يتتبع التغييرات في الكود                    | يستضيف مستودعات Git ويتيح التعاون      |
| **محتاج إنترنت؟** | لأ، بيشتغل أوفلاين                          | أيوه                                   |

---

## 🔧 Git — الأداة نفسها

Git هو نظام تحكم في الإصدارات **موزّع (distributed)**، بيشتغل على جهازك وبيتتبع كل تغيير بتعمله في ملفاتك.

### بيعمل إيه؟

- بيسجل تاريخ كامل لكل تعديل (مين عدّل إيه وامتى وليه).
- بيسمحلك ترجع لأي نسخة قديمة من الكود.
- بيعمل فروع (branches) تجرب فيها ميزات جديدة من غير ما تأثر على الكود الأساسي.
- بيدمج (merge) التغييرات من فروع مختلفة.

### أمثلة أوامر

```bash
git init                 # إنشاء مستودع جديد
git add .                # إضافة التغييرات للمرحلة (staging)
git commit -m "message"  # حفظ التغييرات
git branch feature       # إنشاء فرع
git merge feature        # دمج فرع
git log                  # عرض تاريخ الكوميتس
```

> **مهم:** Git مش محتاج GitHub عشان يشتغل. تقدر تستخدمه بالكامل على جهازك من غير إنترنت.

---

## ☁️ GitHub — المنصة

GitHub هو موقع/خدمة بتستضيف مستودعات Git على السحابة، وبتضيف فوق Git طبقة تعاون واجتماعية.

### بيضيف إيه فوق Git؟

- **استضافة ريموت (remote):** كودك محفوظ على السيرفر، تقدر توصله من أي جهاز.
- **التعاون:** أكتر من شخص يشتغلوا على نفس المشروع.
- **Pull Requests:** آلية لمراجعة الكود قبل دمجه (مش موجودة في Git نفسه).
- **Issues:** تتبع المهام والأخطاء.
- **Actions:** CI/CD (تشغيل اختبارات وبناء تلقائي).
- **Pages:** استضافة مواقع ثابتة مجاناً.
- **المجتمع:** متابعة مشاريع، نجوم (stars)، فوركس (forks).

> **بدائل GitHub:** GitLab، Bitbucket، Gitea — كلها منصات بتستضيف Git زي GitHub.

---

## 🎯 التشبيه اللي بيوضح الفرق

- **Git** = زي Word (البرنامج اللي بتكتب بيه وبيحفظ نسخ).
- **GitHub** = زي Google Docs (منصة سحابية بتستضيف الملفات وتخلي الناس تتعاون عليها).

أو:

- **Git** = المحرك نفسه.
- **GitHub** = العربية اللي بتحط فيها المحرك وتمشي بيها على الطريق.

---

## 🔗 إزاي بيشتغلوا مع بعض

```bash
# 1. تعمل مستودع Git محلياً
git init

# 2. تربطه بمستودع على GitHub
git remote add origin https://github.com/user/repo.git

# 3. ترفع كودك على GitHub
git push -u origin main

# 4. حد تاني ينزّل الكود
git clone https://github.com/user/repo.git
```

- `git push` → ترفع من جهازك لـ GitHub
- `git pull` → تنزّل التحديثات من GitHub لجهازك
- `git clone` → تنسخ مستودع من GitHub بالكامل

## 📌 الخلاصة في سطرين

- **Git** = أداة (برنامج) بتتتبع تاريخ كودك على جهازك — محرك إدارة الإصدارات.
- **GitHub** = منصة سحابية بتستضيف مستودعات Git وتضيف تعاون ومراجعة كود — الواجهة الاجتماعية للكود.

**Git هو الأساس، وGitHub هو واجهة جميلة ومفيدة فوقه.** ممكن تستخدم Git من غير GitHub، لكن GitHub من غير Git مالوش معنى.

# الأوامر التي تعلمتها — ملخص كل أمر

## 🟢 Node.js

| الأمر             | ملخص في سطر                                                       |
| ----------------- | ----------------------------------------------------------------- |
| `node --version`  | يعرض إصدار Node.js المثبت على جهازك (طلع `v22.19.0`).             |
| `node preview.js` | يشغّل ملف JavaScript خارج المتصفح باستخدام Node.js.               |
| `node profile.js` | يشغّل سكريبت Node يطبع بياناتك وإصدار Node عبر `process.version`. |
| `process.version` | (مش أمر، بس خاصية) بترجع إصدار Node الحالي من داخل الكود.         |

## 🔧 Git — إعداد

| الأمر                                  | ملخص في سطر                                                    |
| -------------------------------------- | -------------------------------------------------------------- |
| `git --version`                        | يعرض إصدار Git المثبت.                                         |
| `git config --global --list`           | يعرض كل إعدادات Git العامة (اسمك وإيميلك) للتأكد إنهم مضبوطين. |
| `git config --global user.name "..."`  | يضبط اسمك اللي هيظهر على الكوميتس.                             |
| `git config --global user.email "..."` | يضبط إيميلك (لازم يطابق حساب GitHub).                          |

---

## 🔧 Git — دورة العمل الأساسية

| الأمر                         | ملخص في سطر                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------- |
| `git init`                    | ينشئ مستودع Git جديد في الفولدر الحالي (بيعمل فولدر `.git` مخفي).               |
| `git add .`                   | يضيف كل الملفات المعدّلة لمنطقة الـ staging استعداداً للكوميت.                  |
| `git add <file>`              | يضيف ملف معيّن بس للـ staging.                                                  |
| `git commit -m "message"`     | يحفظ التغييرات المضافة في كوميت برسالة واضحة.                                   |
| `git branch -M main`          | يعيد تسمية الفرع الحالي لـ `main` (الاسم الافتراضي الحديث).                     |
| `git remote add origin <url>` | يربط المستودع المحلي بمستودع GitHub عن بُعد باسم `origin`.                      |
| `git push -u origin main`     | يرفع الكوميتس لأول مرة على GitHub ويربط الفرع المحلي بالبعيد (`-u` = upstream). |
| `git push`                    | يرفع التحديثات اللاحقة على GitHub.                                              |
| `git log --oneline`           | يعرض تاريخ الكوميتس بشكل مختصر (سطر لكل كوميت) — استخدمته لإثبات الـ 4 كوميتس.  |
